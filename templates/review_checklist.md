# 实验方案人工复核清单（模板）

> 用途：在技能输出 `result.json` 之后，按本清单逐项回到原文复核。每个勾选项都应能对应到一条 `locator + quote`；无法定位的项不得勾选。

## 0. 基本信息

- 案例/方案版本：`<case_id / protocol 版本>`
- 复核人：`<姓名>`
- 复核日期：`<日期>`
- 输入清单：`case.json`、`protocol.md`、`inventory.csv`、`<其他材料>`

## 1. 阻断项（任一未关闭即不可行）

- [ ] 伦理触发项已识别：人体 / 动物 / 危险试剂 / 个人数据
- [ ] 伦理批件状态为“已批准”，批件编号与有效期已登记
- [ ] 批件覆盖当前方案版本与样本类型
- [ ] 关键设备/材料不存在“不具备”
- [ ] 样本或时长缺口未超过 50%
- [ ] 若存在 blocker 未满足，结论已写为“不可行”，且给出了关闭条件

## 2. 库存与货期

- [ ] 方案点名的设备型号可在清单中逐行匹配
- [ ] 方案点名的材料/试剂/色谱柱规格可在清单中匹配
- [ ] 清单状态已归一：已具备 / 可外协 / 需采购 / 不具备 / 未知
- [ ] 需采购或可外协项的预计到位时间早于开工时间
- [ ] 样本库存数量已与需求算式核对
- [ ] 清单缺行或规格不符时，未默认判为满足

## 3. 参数域

- [ ] 每个关键参数都有设定值、单位与允许范围
- [ ] 参数名已做同义归一（如柱温/column_temp、流速/flow_rate）
- [ ] 单位换算已核对；无法换算时判为冲突或不确定
- [ ] 每个设定值均落在参数域或设备/安全边界内
- [ ] 越界项已给出调整值或厂家耐受限依据

## 4. 伦理与安全

- [ ] 方案原文与 `case.json#/ethics` 的状态一致
- [ ] 危险试剂/生物安全等级已声明并完成备案
- [ ] 样本采集/入组前置条件已写明
- [ ] 未把“审批中”“未声明”写成“已批准”

## 5. 结论一致性

- [ ] `counts.total == len(checklist)`
- [ ] `findings` 等于全部非 satisfied 条目
- [ ] 结论符合口径：全满足→可行；无 blocker 未满足但有缺口→有条件可行；任一 blocker 未满足→不可行
- [ ] 每个非 satisfied 项都有 `required_condition`
- [ ] 每条 finding 的 `evidence.verified` 为 `true`
- [ ] 时间/样本估算只使用输入明示数字，并附算式
- [ ] 报告中的结论、计数与 `result.json` 完全一致

## 6. 复核记录

| 检查项 | 技能判定 | 复核判定 | 定位 | 备注 |
|---|---|---|---|---|
| `<CHK-xx>` | `<verdict>` | `<同意/修正为…>` | `<file#Lxx / row=N / pointer>` | `<说明>` |

## 7. 未关闭问题

- [ ] 已列出全部未关闭缺口与责任人
- [ ] 已标明复跑条件（补件后重跑或人工关闭）
